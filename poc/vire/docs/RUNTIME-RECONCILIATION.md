# Runtime reconciliation — PoC 001

## Goal
Compare declared Compose services against independently collected runtime observations without granting the VIRE scanner Docker Engine access.

## Inputs
- Declarative inventory JSON generated by `inventory.py`.
- Runtime inventory JSON generated externally (currently a synthetic fixture).

Each runtime service is identified by `compose_file` and `service`. This is a provisional key; future collectors must normalize project identity, service labels and deployment environment.

## Status semantics
- `matched`: runtime and expected immutable image digests agree, and the runtime image reference is not contradictory.
- `drift_detected`: image reference/digest differs, a declared service is stopped, or an unexpected runtime service is present.
- `needs_verification`: runtime data is missing, or immutable digest evidence is incomplete.

A matching mutable tag is **not** proof of identity. A matching digest proves image identity only; it does **not** prove package safety, absence of CVEs, or an effective configuration match.

## Security and limitations
- No Docker socket mount, privileged container, host daemon API calls or remediation execution.
- The runtime fixture is **not authenticated**. Production use requires trusted provenance, freshness, host/project identity, digest normalization and signed or otherwise integrity-protected evidence.
- A collector should run separately with narrowly scoped read permissions and emit sanitized JSON; never grant VIRE Docker administrative privileges.
- Current comparison does not evaluate Dockerfile build context changes, SBOM, runtime environment variables, mounted configs, Kubernetes, or NGINX effective configuration.
- Treat contradictory or stale evidence as `needs_verification` until a trusted collector confirms the deployment.

## Run
```sh
cd poc/vire
docker compose --profile reconcile run --build --rm reconcile
```

The service generates a declarative inventory from the read-only project mount and compares it with a synthetic runtime fixture. The fixture does not represent the actual NGINX container.

## Acceptance tests
Tests cover matching and mismatching digests, missing runtime, stopped service, changed reference, and unexpected runtime services.
